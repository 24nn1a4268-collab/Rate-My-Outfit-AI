# 👗 Rate My Outfit — AI Fashion Critic

An end-to-end AI + Machine Learning + Computer Vision project: dataset ->
preprocessing -> EDA -> transfer-learning classifier -> Vision-Language-Model
powered fashion critic, wrapped in a Streamlit dashboard.

## Project Structure

```
rate_my_outfit/
├── app.py                # Streamlit dashboard (run this)
├── organize_dataset.py   # Auto-sorts raw/unlabeled images into class folders
├── processing.py       # Dataset loading, cleaning, augmentation, splits
├── eda.py                 # Exploratory data analysis charts
├── train.py                # Transfer-learning model + evaluation
├── predict.py               # Full inference pipeline for one photo
├── utils.py                  # Shared config, VLM wrapper, color/rule engine
├── requirements.txt
├── dataset_raw/               # <- put your raw unlabeled images here
├── dataset/                    # <- auto-generated: dataset/<class>/*.jpg
├── saved_models/                # trained model + label map land here
└── reports/                      # saved evaluation metrics (optional)
```

A GPU is strongly recommended for `train.py` and for the Vision-Language
Model (`transformers` + `torch`). Everything also runs on CPU, just slower.

## 2. Prepare the dataset

Your current dataset (per the screenshot) is a **flat folder of raw,
unlabeled images** — random filenames, no folder-per-class structure. Drop
all of those images into `dataset_raw/`, then run:

```bash
python organize_dataset.py --src dataset_raw --dst dataset
```

This uses a CLIP zero-shot classifier (Hugging Face Transformers) to sort
each image into `dataset/<class_name>/` automatically — no manual labeling
needed to get started. Skim each folder afterwards and drag out obvious
mistakes; zero-shot labels are a strong starting point, not perfect ground
truth.

## Notes on the Vision-Language Model

`utils.VisionLanguageCritic` is built around Hugging Face Transformers,
defaulting to `vikhyatk/moondream2` (small and fast). To use LLaVA 1.5
instead, change `VLM_MODEL_ID` in `utils.py` to `"llava-hf/llava-1.5-7b-hf"`
(needs a larger GPU). If model weights can't be downloaded or loaded (no
GPU/internet at demo time), the app automatically falls back to a
deterministic template engine so the roast/hype/summary sections never
break during a live demo.

## Notes on the "fashion intelligence" scores

Trend score, mood, fabric guess, weather compatibility, and similar fields
are generated by a transparent, rule-based engine (`utils.build_full_report`)
driven by the classifier's detected category, extracted colors, and
confidence — there's no public dataset with ground-truth labels for
"trendiness" or "mood," so these are explainable heuristics rather than a
separately trained model. This mirrors how most hackathon-style fashion
demos handle these sections, and keeps every number on screen reproducible.
